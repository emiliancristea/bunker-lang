## 1. Executive Summary & Epistemic Foundations

In native systems compilation, decoupling the compiled code from its runtime library introduces severe ABI (Application Binary Interface) hazards:
1. **Silent Structure Drift**: If a runtime header modifies struct layouts, alignment, or calling conventions without version negotiation, programs compiled against an older header experience silent data corruption and memory faults.
2. **Missing Symbol Traps**: If generated C code calls runtime functions introduced in newer runtime revisions, compiling with an older `runtime.h` produces obscure linker errors at the tail end of the toolchain.
3. **Split-Brain Bootstrapping**: In self-hosting environments, the bootstrap host compiler and the self-host compiler must agree on the exact C ABI signatures to produce deterministically reproducible artifacts.

### The Bunker Principle: Compile-Time Verified Runtime ABI
Bunker solves these hazards through explicit, compile-time runtime ABI versioning:
1. **Locked Semantic Versioning**: The runtime library (`self-host/runtime.h`) declares its exact version via `BKR_RUNTIME_ABI_VERSION_MAJOR`, `BKR_RUNTIME_ABI_VERSION_MINOR`, and `BKR_RUNTIME_ABI_VERSION_PATCH`.
2. **Mandatory Header Requirement Declaration**: Every generated C program declares its expected major ABI version (`#define BKR_REQUIRED_RUNTIME_ABI_MAJOR 1`) before including `runtime.h`.
3. **Fail-Fast Preprocessor Guards**: Any attempt to compile generated C against an incompatible runtime header triggers an immediate compile-time `#error` before parsing functions or structures.
4. **Runtime Version Introspection**: Programs can query their active runtime ABI version at runtime via standard builtins (`runtime_version_major()`, `runtime_version_minor()`, `runtime_version_patch()`, `runtime_version_str()`).
5. **Dual-Compiler Parity**: Both `bunker-cli` (Rust Cranelift JIT) and the self-host compiler (`bkrc.bkr`) expose identical version introspection symbols and return matching values.

## 2. ABI Versioning Specification

The Bunker C runtime ABI follows strict Semantic Versioning:

$$\text{Version} = \text{MAJOR}.\text{MINOR}.\text{PATCH}$$

- **MAJOR (Breaking)**: Incremented when data structures (e.g. `BkrArena`, `bkr_byte_buf_t`, `bkr_slice_t`), calling conventions, memory layout of basic types, or symbol names are modified in an incompatible manner.
- **MINOR (Additive)**: Incremented when new runtime builtins, standard library functions, or non-breaking optimizations are introduced.
- **PATCH (Bugfix)**: Incremented for internal implementation fixes, portability enhancements, or performance improvements that do not alter the API or ABI surface.

### Canonical Version Definition
As of Milestone `Q-288`, the canonical runtime ABI version is locked at **`1.0.0`**:

```c
#define BKR_RUNTIME_ABI_VERSION_MAJOR 1
#define BKR_RUNTIME_ABI_VERSION_MINOR 0
#define BKR_RUNTIME_ABI_VERSION_PATCH 0
#define BKR_RUNTIME_ABI_STRING "1.0.0"
```

## 3. Header Compatibility Guard Architecture

To guarantee that generated C files are never compiled with an incompatible runtime header, Bunker enforces a bidirectional handshake between the compiler and `runtime.h`:

### 3.1 Compiler Emission Contract
Every C file produced by `bunker-cli` or `bkrc.bkr` emits the required ABI major version immediately preceding the header inclusion:

```c
/* Generated by Bunker Compiler */
#define BKR_REQUIRED_RUNTIME_ABI_MAJOR 1
#include "runtime.h"
```

### 3.2 Header Assertion Guard
In `self-host/runtime.h`, the preprocessor verifies compatibility:

```c
#if defined(BKR_REQUIRED_RUNTIME_ABI_MAJOR)
#if BKR_REQUIRED_RUNTIME_ABI_MAJOR != BKR_RUNTIME_ABI_VERSION_MAJOR
#error "Bunker runtime ABI major version mismatch: generated C requires a different runtime.h"
#endif
#endif
```

If a binary generated for ABI Major 1 is compiled against a future ABI Major 2 runtime, compilation fails instantly with a clear diagnostic rather than producing corrupted binaries.

## 4. Runtime Introspection Builtins

Bunker exposes first-class builtins for inspecting the runtime ABI:

| Builtin Signature | Return Type | Semantics | Value for ABI 1.0.0 |
|---|---|---|:---:|
| `runtime_version_major()` | `i64` | Current runtime ABI major version | `1` |
| `runtime_version_minor()` | `i64` | Current runtime ABI minor version | `0` |
| `runtime_version_patch()` | `i64` | Current runtime ABI patch version | `0` |
| `runtime_version_str()` | `str` | Complete semantic version string | `"1.0.0"` |

### 4.1 Programmatic Compatibility Verification
User applications and compiler libraries can dynamically query and assert compatibility:

```bunker
let major: i64 = runtime_version_major();
if major != 1 {
    panic("Unsupported runtime ABI version");
}
```

## 5. Core Type Mappings & C Calling Conventions

The Stable C Runtime ABI defines deterministic representations for all primitive and aggregate types:

| Bunker Type | C ABI Type | Size / Alignment | Representation |
|---|---|:---:|---|
| `i32` | `bkr_i32` (`int32_t`) | 4 bytes / 4 bytes | Two's complement signed 32-bit integer |
| `i64` | `bkr_i64` (`int64_t`) | 8 bytes / 8 bytes | Two's complement signed 64-bit integer |
| `f64` | `bkr_f64` (`double`) | 8 bytes / 8 bytes | IEEE 754 double-precision floating point |
| `bool` | `bkr_bool` (`int`) | 4 bytes / 4 bytes | Boolean integer (`1` = true, `0` = false) |
| `str` | `bkr_str` (`char*`) | 8 bytes / 8 bytes | Null-terminated UTF-8 byte pointer |
| `()` | `void` / `0` | 0 / 8 bytes | Unit type / void expression |
| `struct S` | `struct S` | Derived | Sequential field layout without hidden padding |

| `Result<T, E>` | `bkr_i64` | 8 bytes / 8 bytes | Arena-backed handle (`bkr_result_t` pointer) |
